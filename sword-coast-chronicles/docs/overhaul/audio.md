# audio — synthesis worthy of real polyphony

Owner of `core/audio.js`, the INSTRUMENTS section of `core/music.js`, context
rotation, and the new `core/synth.js` (instrument DSP) plus the dev tools
`tools/music-check.mjs` and `tools/music-render.mjs`.

## Plan (milestones, each committed)

- **M0 baseline.** Render every existing track through the UNMODIFIED engine
  (a fake realtime AudioContext backed by an OfflineAudioContext with
  `suspend()` steps) to `output/music/before/*.wav` with peak / RMS / clip
  counts, so every later change has a before/after.
- **M1 engine.** Split instrument DSP out of audio.js into `core/synth.js`,
  parameterised by an `env` (context + per-context caches), so the same code
  renders live or into an OfflineAudioContext. `Audio.render(trackOrId, opts)`
  is public: composers can render their own tracks. Scheduler walks
  pre-bucketed step arrays with index loops (no per-tick allocation) and widens
  its lookahead when the tab is throttled.
- **M2 rooms + mastering.** Per-track `room` ('hall' | 'chapel' | 'tavern' |
  'open' | 'cave'): procedural stereo IRs (pre-delay, early reflections,
  frequency-dependent decay), cached per room and sample rate, one shared
  convolver per room kind. Music glue compressor + master limiter, calibrated
  by measurement so quiet material is not boosted. Per-track loudness
  normalisation from an offline-measured, gated RMS table
  (`core/music_loudness.js`, regenerated by `tools/music-render.mjs --loudness`).
- **M3 plucked strings.** Karplus-Strong (fractional-delay tuned, pluck-position
  comb, loss filter, baked body resonances) rendered once per (instrument,
  pitch, rate) into cached AudioBuffers with an LRU memory cap and background
  pre-rendering of a track's pitches: lutePlucked (double courses), harpGothic,
  psalteryStruck, citole, gittern; lute / harp / psaltery re-pointed if the
  measurements say KS is better.
- **M4 sung voices.** Formant synthesis: band-limited glottal PeriodicWave,
  jitter + shimmer (per-layer slow noise), vibrato that blooms, onset scoop,
  soft consonant noise burst, breath; 5 bandpass formants per vowel from per-range
  tables (bass / tenor / countertenor / soprano), per-layer bank so vowel morphs
  are smooth automation, F1 tuned up to f0 for high notes. choirMen / choirFull
  are sections with staggered breathing on long notes.
- **M5 winds and bows.** vielle / rebec / viol (bow noise, body, delayed
  vibrato); shawmAlto / shawmTenor / crumhorn / dulcian / chanter / bagpipe
  drone; sackbut / cornett with brass attack brightening.
- **M6 organs, symphonia, bells, percussion.** portative / positive (stopped
  pipe odd partials, chiff, wind), symphonia (wheel tone, key click, trompette
  buzz), bells / handbells rendered from inharmonic partials with per-partial
  decay; drums nakers, nakersHi, tambourine, bellTower, handbell, cymbalettes;
  unknown drum ids are silent.
- **M7 layer options.** vowel, ornament ('mordent' | 'trill' | 'grace' on long
  notes, diatonic neighbours inferred from the track's pitch set), swing,
  humanize (ms), pan.
- **M8 context rotation.** `Audio.music(context)` picks a track seeded by map +
  in-game day, keeps it across maps of the same context, and segues to another
  same-context track after a few loops at a loop boundary. Songbook hooks
  (`Audio.setSongbook({ pinned, banned })`, `Audio.contextTracks(ctx)`) so a UI can
  let the player choose.
- **M9 verify + land.** check tool clean, instrument renders on a scale and a
  chord in `output/music/instruments/`, formant peaks measured by FFT, no clipping
  on the loudest tracks, node counts / render-time CPU proxy, regress suite green.

## Decisions

- Instrument DSP lives in `core/synth.js`; audio.js keeps the context, buses,
  sequencer, rooms/mastering glue and rotation. Everything takes an `env` so the
  live path and `Audio.render()` share one implementation.
- Formant voices use Klatt's CASCADE (five resonant lowpasses in series), not a
  parallel bandpass bank: relative formant levels come out of the physics and
  the fundamental keeps its weight. Measured (output/music/formants.js): F1
  within 0.6 harmonic of the table for all 20 voice x vowel cases; F2 resolved as
  its own peak in 11/20 — the rest are close-F1/F2 back vowels at f0 >= 147 Hz,
  where theory (output/music/cascade.mjs) says F2 is only a shoulder too.
- Loudness: every track is normalised to the median gated loudness (REFERENCE,
  -28.8 dB) within +-9 dB; a track's `gain` is now pure composer intent on top
  (0.7 = -3 dB). Before: tracks spanned -28.8..-42.3 dB; after: -27.1..-31.7.
- Persistent per-layer modulators (jitter, bellows wobble) are linked to each
  note's detune and UNLINKED when that note ends, so an hour-long pinned track
  cannot accumulate dead notes through the modulator's fan-out.

## Done (verified r2)

- M0-M8 were written by the first attempt and verified in r2: modules import
  headless, `tools/music-check.mjs` clean (0 errors), every track renders with
  no NaN / no clipping, before/after table in output/music/compare/stats.json
  (loudness evened out, stereo width corrLR 0.97 -> 0.4-0.9).
- Stress: choirFull + choirMen + positive + bells + nakers at 0.8-0.9 layer
  gains in the chapel: the raw sum peaks +4.6 dBFS (11k clipped samples); through
  the glue + limiter it peaks -5.4 dBFS, 0 clipped. Node cost per second of music:
  stress ~19 osc / 29 gain / 9 biquad; heaviest existing track (battle) 14 / 37 /
  12; offline render 3.5x (stress) to 17x (inn) realtime on the shared laptop.
- `Audio.setPlaceSource` hooked in main.js (map + in-game day seed).
- Loudness table generated (`tools/music-render.mjs --loudness`).
- Karplus-Strong excitation is now the string's slope (harmonics 1/k with the
  pluck-position notches) softened by what plucks it, not flat noise, which was
  ~20 dB too bright by the tenth harmonic: lute centroid 1535 -> 530 Hz, camp
  1540 -> 640, shop 2025 -> 920; gittern / citole / psaltery stay brighter
  (plectrum and quill). `bright` is rate-independent now.
- Every singer in a section wanders in pitch on their own (up to 3 independent
  jitter sources per voice layer); pitch-tracked tenor: jitter-only for the
  first ~0.45 s, then a 5 Hz vibrato of +-10-20 cents.
- The first score's instrument ids that the overhaul re-voiced keep their old
  mix level: both engines rendered on the same probe, gains matched within
  0.2 dB (psaltery and bagpipe deliberately +6 dB: they were near-inaudible).
  Without this, viol / vielle / shawm / bagpipe had jumped 12-25 dB against the
  lute and every consort track's balance was gone.
- Runtime loudness fallback: a track missing from music_loudness.js is
  measured once a session (10 s dry render at 16 kHz, 2.5 s after it starts) and
  eased to the reference; `Audio.loudnessOf(id)`.
- Voice, reed / bow / pipe / wheel and orchestral-section oscillators take
  their pitch modulation at k-rate: dry render of tyrConductus 2.3 s -> 0.8-1.0 s
  per 12 s of music, bindersMotet 1.1 -> 0.34 s; formants, vibrato and trills
  measured unchanged.
- Verified live (fake realtime context, real scheduler): the same map + day
  always opens a context with the same tune and other days differ (temple over
  six days: dawnOrganum x2, temple x2, tyrConductus x2); rotation moves to a
  tune not in the last three at each loop boundary; the loudness fallback fires.
- Layer options: a trilled tenor note has main and upper neighbour equal
  (24 / 25 dB) in its first half and the neighbour 18 dB down after; vowel
  cycles, mordents, graces, swing, humanize, pan, every new drum id and an
  unknown one ('noSuchDrum' is silent) render clean.
- SFX untouched: 14 sfx rendered through both engines match within 1 dB.
  (Fired at t = 0 in a brand-new context they measure softer in the new engine:
  Chrome's DynamicsCompressor starts fully compressed and releases in ~0.3 s.
  In the game that is only ever the first instant after the audio gate opens.)

## Using and extending

- Validate a book: `$NODE tools/music-check.mjs` (headless: unknown instruments
  / drums / rooms / ornaments / vowels / contexts are errors; out-of-compass
  notes and notes past the loop are warnings).
- Hear it without ears: `$NODE tools/music-render.mjs --tracks <ids> --seconds 20`
  writes WAVs to output/music/ and prints peak / gated loudness / crest / clip /
  silence / centroid / stereo correlation; `--instruments <ids|all>` renders a
  scale and a chord per instrument; `--realtime` drives the live scheduler;
  `--script probe.js` runs your own page code with `lib` in scope.
- After adding tracks: `$NODE tools/music-render.mjs --loudness` rewrites
  src/core/music_loudness.js (the runtime fallback covers you until then).
- `gain` on a track is composer intent relative to the reference (0.7 = -3 dB).
  New instrument ids are calibrated so equal layer gains sound about equally
  loud; the first score's ids are at the first score's levels.
- A new instrument is usually just an INSTRUMENTS entry: pick a `kind` ('ks',
  'voice', 'bowed', 'reed', 'brass', 'pipe', 'wheel', 'rbell') and its
  parameters (documented at the top of INSTRUMENTS). Harmonic recipes live in
  synth.js SPECTRA, formant tables in FORMANTS, rooms in ROOMS.
- Rules learned the hard way: never connect a layer-lifetime modulator to a
  note's param without cutting the link when the note ends (see `link()` in
  synth.js); measure an instrument against what it replaces before changing
  its gain, because every track mixed with the old one moves too; a
  DynamicsCompressor has automatic makeup gain (GLUE_TRIM / LIMIT_TRIM cancel
  it, measured).
